# Цагтаа — онлайн цаг захиалгын систем

**Цагтаа** (кодын нэр: `tsagtaa`) бол Улаанбаатарын үйлчилгээний бизнесүүдэд — үсчин, барбер,
маникюр, массаж, гоо сайхан, эмнэлэг, шүдний эмнэлэг, авто засвар, авто угаалга, мал эмнэлэг —
зориулсан онлайн цаг захиалгын вэб аппликейшн юм. Төгсөлтийн дипломын ажлын хүрээнд хөгжүүлж байна.

- **Ажиллаж буй хувилбар:** <https://tsagtaa.vercel.app>
- **Репозитори:** <https://github.com/Tdlgx/Tsagtaa>

> Энэ баримт бичиг төсөл дээр ажиллах хөгжүүлэгчдэд зориулагдсан: төслийг хэрхэн асаах,
> байршуулах, кодын бүтэц яагаад ийм байгаа, юунаас болгоомжлох вэ гэдгийг тайлбарлана.

## Боломжууд

### Үйлчлүүлэгч

- **Сул цаг хайх** (`/search`): ангилал, дүүрэг, өдөр (өнөөдөр, маргааш), өдрийн хэсгээр шүүнэ.
  Нүүр хуудсанд өнөөдрийн сул цагийн самбар байна.
- **Цаг захиалах** (`/book/<slug>`): үйлчилгээ → ажилтан → цаг → холбоо барих мэдээлэл гэсэн 4 алхам.
  Бүртгэлгүй ч захиалж болно; зөвхөн нэр, утас хэрэгтэй.
- **Миний захиалгууд** (`/bookings`): тасалбар, цаг хүртэл үлдсэн хугацаа, цуцлах, календарьт нэмэх.
- **Бүртгэл ба оноо** (`/signup`, `/profile`): нэвтэрсэн үедээ хийсэн захиалга бүр оноо өгч,
  дараагийн захиалгыг хямдруулна.
- **Профайл:** зураг, сануулгын тохиргоо, хэл, өнгөний горим (light/dark).
- **Тусламж** (`/help`) ба **хувийн мэдээллийн бодлого** (`/privacy`).

### Бизнес эзэмшигч ба менежер

- **Бизнесээ бүртгүүлэх** (`/business/register`): 6 алхамтай, автоматаар хадгалагддаг маягт.
  Бүртгүүлсэн хүн шууд эзэмшигчийн бүртгэлтэй болж, нэвтэрнэ.
- **Удирдлагын самбар** (`/dashboard/<slug>`): өнөөдөр, маргаашийн хуваарь, орлого, цуцлалтын хувь,
  захиалга цуцлах, үйлчлүүлэгч «Ирсэн / Ирээгүй» гэж тэмдэглэх, менежер нэмэх, хасах.
- **Цаг, үйлчилгээ, ажилтан засах** (`/dashboard/<slug>/edit`): бүртгэлийн маягтын алхмууд, дүрмээр.
  Захиалга ажилтныг `<slug>-<position>`-оор заадаг тул position хэзээ ч шилжихгүй, дахин ашиглагдахгүй;
  ирэх захиалгатай ажилтныг хасахгүй. Өмнө авсан захиалга хуучин үнэ, цагаараа үлдэнэ.

### Цагтаагийн баг (админ)

- **Бүртгэл шалгах:** автомат шалгалт (давхардал, үнэ, цагийн хуваарь …), зөвшөөрөх, татгалзах,
  түр хаах, дахин нээх.
- **Хэрэглэгчид, захиалга, оноо, үйлдлийн түүх.** Дэлгэрэнгүйг [Админ хэсэг](#админ-хэсэг)-ээс.

## Ашигласан технологи

| Технологи                                                           | Зориулалт                                              |
| ------------------------------------------------------------------- | ------------------------------------------------------ |
| [Next.js 16](https://nextjs.org) (App Router)                       | Full-stack React framework, Server Components, Actions |
| React 19, TypeScript (strict)                                       | UI ба төрлийн аюулгүй байдал                           |
| Tailwind CSS v4                                                     | Стиль (тохиргоо нь CSS дотор `@theme`-ээр)             |
| shadcn/ui (Radix)                                                   | Хүртээмжтэй (accessible) UI компонентууд               |
| Zod 4                                                               | Environment variable болон оролтын шалгалт             |
| PostgreSQL 18 + [postgres.js](https://github.com/porsager/postgres) | Өгөгдлийн сан, ORM-гүй цэвэр SQL                       |
| Docker Compose                                                      | Локал PostgreSQL                                       |
| Vercel + Neon                                                       | Байршуулалт ба үүлэн PostgreSQL                        |
| Vercel Web Analytics                                                | Хуудас үзэлтийн статистик (cookie-гүй)                 |
| Leaflet + OpenStreetMap                                             | Газрын зураг (түлхүүргүй, үнэгүй)                      |
| ESLint 9 (flat config) + Prettier                                   | Кодын чанар ба нэгэн хэвийн формат                     |
| next-themes, sonner                                                 | Light/dark горим, toast мэдэгдэл                       |
| Unbounded + Onest (next/font, cyrillic-ext)                         | Гарчиг ба үндсэн текст, Монгол Ө/Ү бүрэн               |

**Яагаад ORM ашиглаагүй вэ?** Давхар захиалга, оноо зэрэг гол дүрмүүдийг өгөгдлийн сангийн түвшинд
(`EXCLUDE`, `CHECK`, trigger) шийдсэн тул SQL-ийг шууд бичих нь илүү ойлгомжтой, хяналттай.
postgres.js нь tagged template (`` sql`...${value}` ``) ашигладаг тул утга бүр параметр болж
дамжина: SQL injection гарахгүй.

## Локал дээр ажиллуулах

### Шаардлагатай програмууд

- **Node.js 22 буюу түүнээс дээш** — `node -v`
- **npm 10+** — `npm -v`
- **Git** — `git --version`
- **Docker Desktop** (Windows дээр WSL 2-той) — `docker --version`, `docker compose version`

### Алхамууд

Бүх командыг Windows PowerShell дээр, төслийн үндсэн хавтсанд ажиллуулна.

```powershell
# 1. Репозиторийг татах
git clone https://github.com/Tdlgx/Tsagtaa.git tsagtaa
cd tsagtaa

# 2. Багцуудыг суулгах (package-lock.json-д яг заасан хувилбаруудаар)
npm ci

# 3. Environment файл үүсгэх. Дараа нь .env доторх POSTGRES_PASSWORD болон
#    DATABASE_URL доторх нууц үгийг ижилхэн, өөрийн урт нууц үгээр солих.
#    NEXT_PUBLIC_APP_URL-ийг http://localhost:3000 болгох.
Copy-Item .env.example .env

# 4. PostgreSQL контейнерийг асаах (healthy болтол хүлээнэ)
npm run db:up

# 5. Хүснэгтүүдийг үүсгэх (db/migrations доторх SQL-ийг дарааллаар нь нэг удаа ажиллуулна)
npm run db:migrate

# 6. Өөртөө админ бүртгэл үүсгэх (нууц үг командын мөрөнд биш, хувьсагчаар дамжина)
$env:ADMIN_PASSWORD="урт-нууц-үг"; npm run admin:create -- 99112233 "Таны нэр"

# 7. Хөгжүүлэлтийн серверийг асаах
npm run dev
```

Дараа нь шалгах:

- <http://localhost:3000> — нүүр хуудас
- <http://localhost:3000/api/health> — `{ "status": "ok", ... }` буцаана
- <http://localhost:3000/login> — 6-р алхамд үүсгэсэн утас, нууц үгээр нэвтэрч `/admin` руу орно
- `/admin` → «Жишээ бизнесүүдийг оруулах» товч: кодонд байгаа 10 жишээ бизнесийг (төрөл бүрээс нэг) өгөгдлийн санд
  нэмнэ. Ингэснээр тэдэнд эзэмшигч томилж, удирдлагын самбарыг туршиж болно.

> **Зөвлөмж:** `npm install`-ийн оронд `npm ci` ашиглаарай. `npm ci` нь `package-lock.json`-ийг
> өөрчлөхгүй, яг ижил хувилбаруудыг суулгадаг тул «миний компьютер дээр ажиллаж байсан» гэх
> асуудал гардаггүй.

## Script-үүд

| Команд                 | Тайлбар                                                             |
| ---------------------- | ------------------------------------------------------------------- |
| `npm run dev`          | Хөгжүүлэлтийн сервер (http://localhost:3000)                        |
| `npm run build`        | Production build үүсгэнэ                                            |
| `npm run start`        | Build хийсэн аппыг production горимоор ажиллуулна                   |
| `npm run lint`         | ESLint-ээр кодыг шалгана                                            |
| `npm run lint:fix`     | ESLint-ийн автоматаар засаж болох алдааг засна                      |
| `npm run format`       | Prettier-ээр бүх файлыг форматлана                                  |
| `npm run format:check` | Формат зөрсөн файл байгаа эсэхийг шалгана                           |
| `npm run typecheck`    | Route-ийн төрлийг үүсгээд (`next typegen`) TypeScript-ээр шалгана   |
| `npm run db:up`        | PostgreSQL контейнерийг асааж, healthy болтол хүлээнэ               |
| `npm run db:down`      | Контейнерийг зогсооно (өгөгдөл volume-д хадгалагдсан хэвээр)        |
| `npm run db:logs`      | Өгөгдлийн сангийн логийг харна (`Ctrl+C`-ээр гарна)                 |
| `npm run db:migrate`   | `db/migrations/*.sql`-ээс хэрэгжээгүйг нь дарааллаар нь хэрэгжүүлнэ |
| `npm run admin:create` | Цагтаагийн админ үүсгэнэ, эсвэл байгаа бүртгэлийг админ болгоно     |

**Push хийхээс өмнө** дараах гурвыг заавал ажиллуулаарай. Vercel дээр build унахаас сэргийлнэ:

```powershell
npm run lint; npm run typecheck; npm run build
```

## Environment variables

| Нэр                    | Хаана ашиглагдах | Тайлбар                                                           |
| ---------------------- | ---------------- | ----------------------------------------------------------------- |
| `POSTGRES_USER`        | Docker           | PostgreSQL хэрэглэгчийн нэр                                       |
| `POSTGRES_PASSWORD`    | Docker           | PostgreSQL нууц үг                                                |
| `POSTGRES_DB`          | Docker           | Өгөгдлийн сангийн нэр                                             |
| `POSTGRES_PORT`        | Docker           | Компьютер дээрх порт (анхдагч `5432`)                             |
| `DATABASE_URL`         | Зөвхөн сервер    | PostgreSQL холболтын URL. **Нууц.** Vercel дээр заавал тохируулна |
| `NEXT_PUBLIC_APP_URL`  | Сервер + браузер | Сайтын үндсэн хаяг. Vercel дээр тохируулаагүй бол автоматаар      |
| `NEXT_PUBLIC_APP_NAME` | Сервер + браузер | Аппын нэр. Тохируулаагүй бол «Цагтаа»                             |

- Бүх утгыг апп асах үед `src/lib/env-schema.ts` дахь Zod схемээр шалгадаг. Утга дутуу эсвэл буруу
  бол апп асахгүй бөгөөд аль хувьсагч ямар алдаатайг монголоор жагсааж харуулна.
- `NEXT_PUBLIC_` угтвартай хувьсагч **браузерт ил харагддаг**. Тэнд нууц мэдээлэл хэзээ ч бүү хадгал.
- Vercel дээр `NEXT_PUBLIC_APP_URL` тохируулаагүй бол Vercel-ийн өгдөг `VERCEL_PROJECT_PRODUCTION_URL`-ээс,
  `NEXT_PUBLIC_APP_NAME` тохируулаагүй бол «Цагтаа»-г `next.config.ts` автоматаар оноодог.
- Neon-ы холболтын URL-ийн төгсгөлд байдаг `channel_binding=require`-ийг postgres.js дэмждэггүй тул
  `src/lib/db.ts` болон `scripts/*.mjs` түүнийг автоматаар хасдаг. URL-ээ Neon-ы өгснөөр нь хуулж болно.

## Vercel-д байршуулах

`main` салбар руу push хийх бүрт Vercel автоматаар шинэ build хийж, сайтыг шинэчилнэ.

### Анх удаа тохируулах

1. **Үүлэн өгөгдлийн сан үүсгэх.** Vercel төсөл → **Storage** → **Create Database** → **Neon (Postgres)**.
   Төсөлтэйгөө холбоход `DATABASE_URL` автоматаар нэмэгдэнэ. (Neon нь бидэнд хэрэгтэй `btree_gist`,
   `pg_trgm` өргөтгөлүүдийг дэмждэг.)
2. **Хүснэгтүүдийг үүсгэх.** Өөрийн компьютерээс, Neon-ы URL-ийг ашиглан:

   ```powershell
   $env:DATABASE_URL="postgresql://...neon.tech/neondb?sslmode=require&channel_binding=require"
   npm run db:migrate
   ```

   Shell-д тохируулсан хувьсагч `.env` файлынхаас давуу эрхтэй тул энэ команд локал биш, үүлэн
   өгөгдлийн сан руу ажиллана. `0001`–`0004` бүрийн өмнө `✓` гарах ёстой.

3. **Админ үүсгэх** (ижил терминалд): `$env:ADMIN_PASSWORD="урт-нууц-үг"; npm run admin:create -- 99112233 "Нэр"`
4. **Redeploy.** Vercel → Deployments → **⋯** → **Redeploy**. Environment variable-ийг зөвхөн
   дараагийн build-үүд хардаг.
5. **Analytics асаах.** Vercel төсөл → **Analytics** → **Enable**.
6. Сайт дээр `/login` → `/admin` → «Жишээ бизнесүүдийг оруулах».

### Шинэ migration нэмсний дараа

Код push хийхэд хүснэгт **автоматаар өөрчлөгдөхгүй**. Шинэ `.sql` файл нэмсэн бол push хийхээс
өмнө 2-р алхмын командыг дахин ажиллуулаарай. Эс бөгөөс шинэ код хуучин хүснэгттэй ажиллаж алдаа гарна.

> **Анхаар:** Локал өгөгдлийн сан ба үүлэн өгөгдлийн сан тусдаа. Локал дээр бүртгүүлсэн
> бизнес, бүртгэл үүлэн дээр байхгүй.

## Өгөгдлийн сан ба migration

Хүснэгтүүдийг `db/migrations/` доторх SQL файлууд үүсгэнэ. `npm run db:migrate` нь хэрэгжсэн
файлуудыг `schema_migrations` хүснэгтэд тэмдэглэж, шинээр нэмэгдсэнийг л дарааллаар нь ажиллуулна.
Файл бүр өөрийн транзакцид ажилладаг тул алдаа гарвал хагас дутуу өөрчлөлт үлдэхгүй.
Хоёр хүн зэрэг ажиллуулбал advisory lock нэгийг нь хүлээлгэнэ.

| Файл                                   | Агуулга                                                                            |
| -------------------------------------- | ---------------------------------------------------------------------------------- |
| `0001_bookings.sql`                    | Захиалга, давхар захиалгыг хориглох `EXCLUDE` constraint                           |
| `0002_businesses.sql`                  | Бизнес, ажлын цаг, үйлчилгээ, ажилтан                                              |
| `0003_accounts.sql`                    | Бүртгэл, эрх (эзэмшигч, менежер), нэвтрэлтийн session                              |
| `0004_points_and_admin.sql`            | Оноо, онооны дүрэм, бизнесийг түр хаах, админы үйлдлийн түүх, `pg_trgm`            |
| `0005_business_media_and_location.sql` | Бизнесийн лого, зураг (`business_images`), газрын зураг дээрх байршил              |
| `0006_fewer_samples.sql`               | Жишээ бизнесийг төрөл бүрээс нэг болгож, хасагдсан 9-ийг өгөгдлийн сангаас устгана |

### Шинэ migration нэмэх дүрэм

- Дараагийн дугаартай **шинэ** файл үүсгэ: `0005_<юу_хийх>.sql`.
- **Хэрэгжсэн migration-ийг хэзээ ч бүү засварла.** Тэр файл аль хэдийн хэрэгжсэн өгөгдлийн санд
  дахин ажиллахгүй тул таны засвар тэнд хүрэхгүй, өгөгдлийн сангууд бие биеэсээ зөрнө.
- Хүснэгтийн нэр, баганыг өөрчлөхдөө одоо байгаа өгөгдлийг алдагдуулахгүй байхыг бод
  (`ALTER TABLE … ADD COLUMN … DEFAULT …`).
- Эхлээд локал дээр, дараа нь үүлэн өгөгдлийн сан дээр ажиллуулна.

│   ├── (admin)/            # Цагтаагийн админ (/admin/...)

│   ├── api/health/         # Системийн эрүүл мэндийн шалгалт
│   ├── layout.tsx          # Root layout: фонт, theme, хэл, Analytics
│   ├── not-found.tsx       # 404 хуудас
│   ├── error.tsx           # Алдааны хуудас
│   └── global-error.tsx    # Root layout-ийн алдааны нөөц хуудас
├── components/
│   ├── ui/                 # Суурь компонентууд (Button, Input, Badge …)

`features/` доторх модуль бүр өөрийн өгөгдлийн санд хандах (`*-db.ts`, `server-only`),

## Нэвтрэлт ба эрх

- **Нэвтрэх** (`/login`) нь бүх хүнд нэг: үйлчлүүлэгч, эзэмшигч, менежер, админ. Нэвтэрсний дараа
  эзэмшигч/менежер `/dashboard`, админ `/admin`, үйлчлүүлэгч `/profile` руу орно.
- **Утас эсвэл имэйлээр** нэвтэрнэ: нэг талбарт `@` байвал имэйл, үгүй бол утас гэж уншина.
  Утас нууц үгээр, **имэйл нууц үггүй, 6 оронтой кодоор** нэвтэрнэ
  ([src/features/auth/email-codes.ts](src/features/auth/email-codes.ts)). Код 10 минут, нэг удаа
  хүчинтэй; 5 буруу оролдлогоор хүчингүй болно; нэг хаяг руу минутад 1, цагт 5 хүртэл код. DB-д
  зөвхөн кодын hash хадгалагдана. Бүртгэлгүй имэйлд ч «код илгээлээ» гэж ижил харагдана (имэйл
  явуулахгүй), тиймээс хэн бүртгэлтэйг тааж олохгүй.
- **Имэйл нэмэх, солих** (бүртгүүлэхдээ эсвэл `/profile`): одоогийн нууц үг → шинэ хаяг руу код →
  кодыг оруулсны дараа л хадгалагдана. Бусдын хаягийг өөртөө холбох боломжгүй.
- **Имэйл илгээх** ([src/lib/email.ts](src/lib/email.ts)): `SMTP_USER` байвал SMTP-ээр (Gmail + App
  Password, домэйн хэрэггүй, өдөрт ~500), үгүй бол `RESEND_API_KEY` байвал [Resend](https://resend.com)-ээр
  (өөрийн домэйн шаардана; `*.vercel.app`-ийг баталгаажуулах боломжгүй). Аль нь ч байхгүй бол
  хөгжүүлэлтэд код `npm run dev`-ийн terminal-д хэвлэгдэнэ, production-д «имэйл илгээж чадсангүй».
- **Нууц үг** scrypt-ээр хэшлэгдэнэ; нууц үг өөрөө хаана ч хадгалагдахгүй.
- **Session:** cookie-д санамсаргүй токен, өгөгдлийн санд зөвхөн түүний SHA-256 хадгалагдана.
  Өгөгдлийн сан алдагдсан ч түүгээр нэвтрэх боломжгүй. Хугацаа 30 хоног.
- **Brute-force хамгаалалт:** 5 удаа буруу оруулбал бүртгэл 15 минут түгжигдэнэ. Байхгүй утас,
  буруу нууц үг хоёрт ижил хариу, ижил хугацаанд өгдөг тул хэн бүртгэлтэйг тааж олох боломжгүй.
- **Эрхийн шалгалт сервер талд:** хуудас ба Server Action бүр `requireAccount`, `requirePlatformAdmin`,
  `requireBusinessAccess`-ийн аль нэгийг дуудна ([src/lib/auth/session.ts](src/lib/auth/session.ts)).
  Server Action-ыг хэн ч шууд POST-оор дуудаж чадах тул UI-д товч нуух нь хамгаалалт биш.
- **Эрхгүй хүнд** хуудас «олдсонгүй» (404) гэж харагдана: хуудас байгаа эсэхийг ч мэдэгдэхгүй.
- **Нууц үг мартвал:** админ `/admin/accounts` дээр «Нууц үг шинэчлэх» дарна. Шинэ нууц үг зөвхөн
  нэг удаа харагдах бөгөөд тухайн хүний бүх төхөөрөмжөөс гаргана.

> **Зөвлөмж:** Шинэ хуудас эсвэл Server Action нэмэхдээ эрхийн шалгалтыг **хамгийн эхэнд** нь
> бич. Эрх шаардсан өгөгдөлд эрх шалгахгүйгээр хандах код бүү бич.

## Захиалга ба давхар захиалгаас хамгаалах

Нэг ажилтны нэг цагийг хоёр хүн зэрэг авахыг **өгөгдлийн сан өөрөө** хориглодог
([db/migrations/0001_bookings.sql](db/migrations/0001_bookings.sql)):

- **`bookings_no_overlap`** (`EXCLUDE USING gist`): нэг бизнесийн нэг ажилтанд баталгаажсан хоёр
  захиалгын цаг огт давхцаж болохгүй. `UNIQUE (staff_id, starts_at)` хангалтгүй: 10:00-ийн
  45 минутын захиалга, 10:30-ийн захиалга хоёулаа орчихно. Цуцалсан захиалга тооцогдохгүй тул цаг
  шууд чөлөөлөгдөнө.
- **`request_id` UNIQUE**: давхар товшилт, сүлжээний дахин оролдлого нэг л захиалга үүсгэнэ.
- **«Сул эсэхийг шалгаад дараа нь оруулах» код байхгүй:** шалгалт, оруулалтын хооронд өөр хүн цагийг
  авч болно. Оруулалт constraint-д тээглэвэл (`23P01`) «Аль ч ажилтан» сонголтод дараагийн сул
  ажилтныг savepoint-оор оролдоно, үгүй бол хэрэглэгчид «цаг авагдсан» гэж хэлнэ
  ([booking-db.ts](src/features/booking/booking-db.ts)).
- **Серверт итгэх:** үнэ, үргэлжлэх хугацаа, ажилтан, цагийг браузерээс биш, сервер өөрөө тооцдог.
- **Түр хаагдсан** бизнес шинэ захиалга авахгүй.

### Хайлтад гарах бизнесүүд

Хайлт, нүүрний самбар, захиалгын хуудас хоёр эх сурвалжийг нэгтгэдэг ([src/features/business/listings.ts](src/features/business/listings.ts)):

- **Жишээ бизнесүүд** — кодонд, төрөл бүрээс нэг (10).
- **Бүртгүүлж, зөвшөөрөгдсөн бизнесүүд** — өгөгдлийн сангаас. Сул цаг нь өөрийн ажлын цаг, цагийн алхмаас
  (15/30/60 мин) гарна; үйлчилгээ хаах цагаас өмнө дуусах ёстой (сервер ч шалгана). Сэтгэгдэлгүй тул одны
  оронд «Шинэ» тэмдэгтэй. Сайтын хуваарь 09:00–21:00 тул түүнээс гадуурх цаг харагдахгүй.

## Лого, зураг, газрын зураг

- **Лого, зураг:** бизнес удирдлагын самбараасаа лого (1) ба зураг (6 хүртэл) оруулна. Зургийг хөтөч дотор нь
  жижигрүүлж (лого 256px, зураг 1600px хүртэл, WebP), байршил зэрэг EXIF мэдээллийг арилгадаг. Сервер файлын
  төрлийг агуулгаас нь (WebP/JPEG) шалгана; SVG зэргийг хүлээж авахгүй. Зураг PostgreSQL-д (`business_images`)
  хадгалагдаж `/api/business-images/<id>`-ээр нэг жилийн cache-тэй үйлчилнэ. Шалгагдаж буй бизнесийн зураг
  зөвхөн тухайн баг ба админд харагдана.
- **Байршил:** бүртгэлийн маягт болон удирдлагын самбарт газрын зураг дээр дарж эсвэл «Миний байршил»-аар
  тэмдэглэнэ. Зөвхөн Улаанбаатар орчмын цэгийг хүлээж авна (өгөгдлийн сан ч шалгадаг).
- **Газрын зураг** (`/map`): идэвхтэй, байршилтай бүх бизнес; шинээр нэгдсэн нь «Шинэ» тэмдэгтэй эхэнд.
  Жишээ бизнесүүд ойролцоо байршилтай (`src/features/business/locations.ts`); өмнө нь оруулсан бол
  `/admin` → «Жишээ бизнесүүдийг оруулах»-ыг дахин дарахад байршил нь нэмэгдэнэ.
- **Газрын зургийн tile:** OpenStreetMap-ийн үнэгүй tile. Хэрэглээ ихэсвэл төлбөртэй tile үйлчилгээ рүү шилжих
  хэрэгтэй ([OSM-ийн бодлого](https://operations.osmfoundation.org/policies/tiles/)).

## Оноо

1 оноо = 1₮ хөнгөлөлт ([db/migrations/0004_points_and_admin.sql](db/migrations/0004_points_and_admin.sql)).
Дүрмийг админ `/admin/points` дээр өөрчилнө:

| Дүрэм       | Анхдагч | Тайлбар                                              |
| ----------- | ------- | ---------------------------------------------------- |
| Олгох хувь  | 5%      | Төлсөн дүнгийн хэдэн хувь нь оноо болох              |
| Доод хэмжээ | 1,000   | Үүнээс бага оноог захиалгад ашиглахгүй               |
| Дээд хувь   | 50%     | Нэг захиалгын үнийн хэдэн хувийг оноогоор төлж болох |

- **Олгох:** зөвхөн нэвтэрсэн үедээ хийсэн захиалга оноо өгнө. Бизнес «Ирсэн» гэж тэмдэглэхэд,
  эсвэл үйлчилгээ дууссанаас 24 цагийн дараа автоматаар орно. «Ирээгүй» бол олгохгүй.
  Олгох оноо захиалах үед тогтоогддог тул дараа нь дүрэм өөрчлөгдсөн ч амласан оноо хэвээр.
- **Зарцуулах:** захиалга хадгалах ба оноо хасах нь **нэг транзакц**: аль аль нь болно, эсвэл
  аль нь ч болохгүй. Цуцлах, «Ирээгүй» бол зарцуулсан оноо буцаж орно.
- **Хэн төлөх вэ:** одоогоор хөнгөлөлтийг Цагтаа нөхнө. Бизнес бүтэн үнээ авна гэж үзсэн бөгөөд
  удирдлагын самбарт захиалга бүр дээр бичигдсэн байдаг.

### Өгөгдлийн сангийн баталгаа

- `points_ledger` нь **зөвхөн нэмэгддэг**: мөрийг засах, устгахыг trigger хориглоно. Алдааг
  «залруулга» мөрөөр засна.
- `accounts.points_balance`-ийг **зөвхөн** ledger-ийн trigger өөрчилнө. Шууд `UPDATE` хийвэл алдаа өгнө.
- `CHECK (points_balance >= 0)`: хоёр захиалга зэрэг оноо зарцуулсан ч үлдэгдэл сөрөг болохгүй.
  Хоёр дахь нь мөрийн түгжээг хүлээгээд, багассан үлдэгдлийг хараад унана.
- `UNIQUE (booking_id, kind)`: нэг захиалга нэг л удаа оноо олгож, хасаж, буцаана.
- Залруулга хийсэн админыг устгах боломжгүй (`ON DELETE RESTRICT`): түүх «хэн хийсэн»-ийг хадгална.
  Хэрэгтэй бол админ эрхийг нь хасна.

## Админ хэсэг

Зөвхөн `is_platform_admin = true` бүртгэлтэй хүн нэвтэрнэ. Анхны админыг `npm run admin:create`-ээр үүсгэнэ.

| Хуудас                 | Боломж                                                                     |
| ---------------------- | -------------------------------------------------------------------------- |
| `/admin`               | Тойм: тоо баримт, шалгах бүртгэл, сүүлийн захиалга, сүүлийн үйлдлүүд       |
| `/admin/review`        | Шалгах бүртгэлүүд, хамгийн удаан хүлээсэн нь эхэндээ, автомат үнэлгээтэй   |
| `/admin/places/<slug>` | Бүртгэлийн бүх мэдээлэл, 13 автомат шалгалт, шийдвэр, хүн томилох, түүх    |
| `/admin/places`        | Бүх бизнес, төлөвөөр шүүх, нэр, утас, регистрээр хайх                      |
| `/admin/accounts`      | Хэрэглэгч хайх, түгжээ тайлах, нууц үг шинэчлэх, админ эрх, оноо залруулах |
| `/admin/bookings`      | Захиалгын код, утас, хаягаар хайх, цуцлах (оноо буцна)                     |
| `/admin/points`        | Онооны дүрэм, эргэлтэд буй оноо, хамгийн их оноотой хэрэглэгчид            |
| `/admin/activity`      | Багийн үйлдэл бүр. Өөрчлөлттэйгээ нэг транзакцид бичигддэг тул алдагдахгүй |

**Автомат шалгалтууд:** эзэмшигч байгаа эсэх, регистрийн дугаар, давхардал (`pg_trgm`-ээр нэрийн
төстэй байдал + ижил утас, эзэмшигч, регистр), нэрийн бичиглэл, хаяг, цагийн хуваарь, үнэгүй
үйлчилгээ, үнэ ижил төрлийн бизнесүүдийн дундажаас хэт зөрүүтэй эсэх, үйлчилгээ ажлын өдөрт багтах
эсэх, ажилтан, танилцуулга, имэйл, хүлээсэн хугацаа. Шалгалт зөвхөн зөвлөмж: шийдвэрийг хүн гаргана.

**Төлөвийн шилжилт:** шалгагдаж байна → идэвхтэй / татгалзсан; идэвхтэй ↔ түр хаагдсан;
татгалзсан → дахин шалгах. Татгалзах, түр хаахад шалтгаан заавал бичнэ; эзэмшигчид харагдана.

## Төхөөрөмж дээрх өгөгдөл

Профайл (нэр, имэйл, зураг, тохиргоо) болон «Миний захиалгууд»-ын жагсаалт хөтчийн `localStorage`-д
хадгалагдана ([src/lib/local-store.ts](src/lib/local-store.ts)).

- **Бүртгэл бүрт тусдаа:** нэвтэрсэн бүртгэл бүр өөрийн хуулбартай; нэвтрээгүй үед бас тусдаа.
  Нэг төхөөрөмж дээр өөр хүн нэвтэрвэл өмнөх хүний мэдээлэл харагдахгүй
  ([src/components/shared/storage-scope.tsx](src/components/shared/storage-scope.tsx)).
- **Профайл зураг** төхөөрөмжөөс гардаггүй: 320px JPEG болгон жижигрүүлж, байршил зэрэг EXIF
  мэдээллийг арилгадаг.
- Захиалга өөрөө серверт хадгалагддаг; `localStorage` дахь нь түүний хуулбар.

## Хэл (MN/EN)

- Хэрэглэгчид харагдах бүх текст `src/i18n/dictionaries/mn.ts` (эх хэл) ба `en.ts`-д байна.
  `en.ts` нь `mn.ts`-тэй яг ижил бүтэцтэй байх ёстой; дутуу орчуулга build-ийг унагана.
- Сонгосон хэл cookie-д хадгалагдана. Тоо, нэр орсон өгүүлбэр нь функц:
  `` reviews: (count: number) => `${count} сэтгэгдэл` ``.
- **Монгол текст бичих зөвлөмж:**
  - Машин орчуулга шиг биш, өдөр тутмын ярианы хэлээр бич. Бичээд чангаар уншиж үз.
  - Бизнес эзэмшигчид хандахдаа «газар» биш «бизнес» гэж бич («Бизнес эрхэлдэг үү?»).
    Үйлчлүүлэгчид «очдог газар», «газар дээр нь төлнө» зэрэг байгалийн хэллэгийг хэвээр үлдээж болно.
  - Хэн, хэнд хандаж байгааг шалга: «Бизнес тантай холбогдоно» зөв, «Газар тань руу холбогдоно» буруу.
  - Нэг ойлголтод нэг үг: «захиалга», «цуцлах», «баталгаажуулах», «оноо».

## Хувийн мэдээллийн хамгаалалт

Монгол Улсын **Хүний хувийн мэдээлэл хамгаалах тухай хууль**-ийг мөрдөнө. Бодлого `/privacy` хуудсанд.

- Захиалга, бүртгэлийн өмнө **тусгай зөвшөөрөл** авна (checkbox урьдчилан чагтлагдаагүй),
  зөвшөөрсөн цагийг өгөгдлийн санд тэмдэглэнэ.
- Хамгийн бага мэдээлэл: нэр, утас. Регистр, байршил, картын мэдээлэл авдаггүй.
- Захиалгын мэдээлэл зөвхөн тухайн бизнест харагдана.
- Vercel Analytics cookie хэрэглэдэггүй, хувь хүнийг танихгүй.

> мөн шинэчил.

## Дизайн систем «Хөх цаг»

`npm run dev` ажиллуулаад <http://localhost:3000/design-system> хуудсыг нээнэ. Production горимд
энэ хуудас 404 буцаадаг.

- **Token-ууд:** `src/app/globals.css`. Өнгө, фонтын хэмжээ, radius, сүүдэр, хөдөлгөөн бүгд энд.
  Tailwind-ийн анхдагч палитр, хэмжээг санаатай устгасан тул `text-gray-500`, `text-5xl` мэт
  утга **ажиллахгүй**. Зөвхөн token-уудыг ашигла (`text-muted-foreground`, `text-4xl` хүртэл).
- **Суурь компонентууд:** `src/components/ui/`. **Аппын компонентууд:** `src/features/*/components/`.
- **3D карт:** `TiltCard` ([src/components/shared/tilt-card.tsx](src/components/shared/tilt-card.tsx))
  нь курсор, хуруу дагаж хазайж, гэрэл тусдаг. «Reduce motion» тохиргоог хүндэтгэнэ.
- Текст ба дэвсгэрийн бүх хослол light, dark хоёр горимд WCAG AA (≥ 4.5:1) хангана.

## Кодын дүрэм

- Файлын нэр `kebab-case` (`booking-form.tsx`), компонентын нэр `PascalCase`.
- Анхдагчаар Server Component; `"use client"` зөвхөн state, event, browser API хэрэгтэй үед.
- Өгөгдлийн санд хандах файлын эхэнд `import "server-only";`: браузер руу алдаатай орвол build унана.
- `any` хэрэглэхгүй, функц бүр буцаах төрлөө тодорхой заана (ESLint шалгана).
- Хэрэглэгчид харагдах текст dictionary-д, код дахь нэр болон тайлбар англиар.
- Огноо, цагийг үргэлж `src/lib/date.ts`-ээр (`Asia/Ulaanbaatar` бүсээр) харуулна.
- Мөнгийг `formatMNT()`-ээр (`25,000₮`), оноог `formatPoints()`-оор харуулна.
- Энэ төсөл **Next.js 16**: API, дүрэм нь өмнөх хувилбаруудаас зөрдөг. Код бичихээс өмнө
  `node_modules/next/dist/docs/`-ийг уншаарай ([AGENTS.md](AGENTS.md)).

## Зөвлөмж ба анхааруулга

### Хийж болохгүй

- **`npm audit fix --force` бүү ажиллуул.** «Засахын» тулд хуучин, тохирохгүй хувилбар суулгадаг
  (жишээ нь `eslint-config-next`-ийг 16-аас 14 руу буулгасан). Үлдсэн анхааруулгууд нь зөвхөн
  хөгжүүлэлтийн хэрэгслүүдэд (ESLint, shadcn CLI) байдаг бөгөөд сайт руу ордоггүй. Шалгах бол:
  `npm audit --omit=dev` → `found 0 vulnerabilities` байх ёстой. Энгийн `npm audit fix` (`--force`-гүй) аюулгүй.
- **`.env`-ийг commit бүү хий.** `.gitignore`-д байгаа. Нууц үг, холболтын URL зөвхөн `.env` болон
  Vercel-ийн тохиргоонд.
- **Хэрэгжсэн migration-ийг бүү засварла.** Шинэ файл нэм.
- **`NEXT_PUBLIC_` хувьсагчид нууц мэдээлэл бүү хий.**
- **Өгөгдлийн сангийн дүрмийг кодоор тойрох гэж бүү оролд** (жишээ нь `points_balance`-ийг шууд
  өөрчлөх). Дүрмүүд санаатайгаар өгөгдлийн санд байгаа.

### Хийх нь зүйтэй

- Push хийхийн өмнө `npm run lint; npm run typecheck; npm run build`.
- Багц нэмэхдээ `npm i <нэр>`, дараа нь `package.json`, `package-lock.json` хоёуланг нь commit хий.
- Шинэ хуудас, Server Action бүрт эрхийн шалгалт.
- Шинэ текстийг `mn.ts` ба `en.ts` хоёуланд нэм.
- Утсан дээр (360px өргөн) болон dark горимд шалгаж үз.
